# AI Agent Policy
**Project:** Hime Assistant  
**Version:** 1.0  
**Effective Date:** 2026-11-06  

---

## 1. Purpose & Authority

This document defines the operational boundaries, ethical guidelines, and execution standards for all Autonomous AI Coding Agents operating within the Hime Assistant workspace. 

All agents (whether run via Antigravity, Claude Code, Codex, or headless harnesses) are bound by this policy and the root [`AGENTS.md`](file:///x:/folder_ai/Hime/AGENTS.md).

---

## 2. Operational Rules of Engagement

### 2.1 Least Privilege & Execution Scope
- Agents must operate strictly within the boundaries of the assigned task specification.
- Agents must never initiate tasks outside their approved scope or make architectural alterations without explicit approval.
- Agents must not run speculative commands or probe local network/host infrastructure beyond task requirements.

### 2.2 Truthfulness & Evidence-First Reporting
- Fabricating build results, test outcomes, benchmark metrics, or file states is strictly prohibited.
- Every claim made in completion reports or PR summaries must cite observable proof (command output, file paths, test assertions).
- Agents must explicitly classify claims using standard labels:
  - `[VERIFIED]`: Confirmed directly via terminal command, test execution, or disk inspection.
  - `[OBSERVED]`: Seen in runtime logs or process lists but not independently validated.
  - `[INFERRED]`: Deduced through engineering logic from verified facts.
  - `[UNKNOWN]`: Unresolved or unverified facts requiring human clarification.

### 2.3 Idempotency & Clean Workspace
- Agents must not create dangling temporary files outside designated scratch directories (`<appDataDir>/brain/<id>/scratch/`).
- Agents must not leave commented-out code, debug print statements, or dead imports in production files.
- Agents must never bypass linters, typecheckers, or git hooks using bypass flags (e.g., `--no-verify`, `--skip-checks`) unless explicitly instructed by the user.

---

## 3. Human-in-the-Loop & Approval Gates

Human review and approval is mandatory before an agent executes:
1. **Destructive Filesystem Operations:** Deleting non-temporary files, dropping database tables, or purging git history (`git reset --hard`, `git push --force`).
2. **Credential & Secret Operations:** Accessing, generating, or modifying tokens, API keys, or security certificates.
3. **External Network Exposure:** Modifying firewall rules, binding servers to `0.0.0.0`, or dispatching telemetry data outside localhost.
4. **Dependency Tree Modifications:** Adding new runtime dependencies or updating major framework versions in `package.json`, `Cargo.toml`, or `pyproject.toml`.

---

## 4. Subagent Governance

When an agent spawns child agents or subagents (`invoke_subagent`):
- The parent agent remains fully responsible for the output, safety, and correctness of the child agents.
- Child agents must be assigned a tightly-scoped, single-purpose prompt.
- Subagents must not spawn recursive trees of unmanaged subagents.
- All files generated by subagents must be audited by the parent agent before task completion.

---

## 5. Violation Handling

If an agent encounters a policy violation, environmental block, or unauthorized command request:
1. Immediately halt execution.
2. Log the violation or blockage in the task notes.
3. Report the block to the user with actionable next steps.
