# Security Policy
**Project:** Hime Assistant  
**Version:** 1.0  
**Effective Date:** 2026-11-06  

---

## 1. Security Architecture Principles

Hime Assistant combines a native desktop shell (Tauri Rust), an autonomous Python agent (Hermes Agent), a Node.js routing gateway (9Router), and a mobile client (Android Kotlin). Security must be designed into every interaction boundary.

### 1.1 Localhost Isolation
- All inter-process communication (IPC), local REST endpoints, WebSocket streams, and Named Pipes must bind **strictly to `127.0.0.1` (loopback)**.
- Binding to `0.0.0.0` or exposing ports to local area networks (LAN) is strictly forbidden unless explicitly enabled by the user in Remote Execution mode with cryptographic mutual TLS (mTLS).

### 1.2 Secrets & Credential Management
- **Zero Hardcoded Secrets:** No API keys, session tickets, private keys, or passwords may be committed to version control.
- **Windows DPAPI Storage:** On Windows desktop, persistent credentials (API keys, provider tokens) must be encrypted using Windows Data Protection API (`CryptProtectData`) before being stored on disk.
- **Filesystem Access Control Lists (ACL):** Sensitive directories such as `%USERPROFILE%\.9router` and `%USERPROFILE%\.hermes` must be restricted using Windows ACLs (`icacls`) so that only the current user session has read/write privileges.

### 1.3 9Router & Hermes Specific Security Requirements
- **Default Password Remediation:** The hardcoded default password (`INITIAL_PASSWORD="123456"`) in 9Router must be programmatically replaced with a cryptographically secure random string during the first initialization by Hime Native Core.
- **Anti-IP Spoofing:** In 9Router, `custom-server.js` must strictly read IP addresses from raw TCP sockets (`req.socket.remoteAddress`) and never trust client-controlled `X-Forwarded-For` headers on local loopback routes.
- **Hermes Named Pipe Ticket Auth:** All IPC connections to the Hermes gateway Named Pipe (`\\.\pipe\hermes-gateway-<hash>`) must require one-time cryptographic session tickets generated by the parent Hime process.
- **Tool Execution Approval Gate:** High-risk tool calls (filesystem wipe, command execution, network requests) must default to Manual Gate or Smart Guardian validation, never unverified YOLO mode.

## 2. Vulnerability Severity & SLA

| Severity | Definition | Target Remediation Window |
|:---|:---|:---:|
| **Critical** | Remote Code Execution (RCE), token extraction, privilege escalation, unauthenticated port exposure | < 24 Hours |
| **High** | Path traversal, arbitrary local file read, denial of service via malformed SSE stream | < 72 Hours |
| **Medium** | Missing rate limits on local endpoints, plaintext cache of non-credential data | < 7 Days |
| **Low** | Verbose error stack traces, minor information disclosure | Next Release Cycle |

---

## 3. Security Review Gates

A formal Security Review (`docs/security/SECURITY_REVIEW_TEMPLATE.md`) is mandatory whenever a change touches:
1. Authentication or authorization logic (JWT, session tickets, tokens).
2. Tauri IPC command definitions (`#[tauri::command]`) or WebView capability scopes (`capabilities/*.json`).
3. Execution of shell scripts or child processes (`std::process::Command`, `subprocess.Popen`).
4. Network transport handlers (proxying, custom HTTP headers, WebSocket handlers).
5. Storage of user credentials or database schemas storing auth data.
